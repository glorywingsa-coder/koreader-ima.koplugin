# IMA 知识库 · KOReader 插件（v0.6.26）

在 KOReader（Kobo 等设备）里浏览、检索并**在线阅读**腾讯 **ima 个人知识库**。

走的是 ima **官方开放平台接口**，不是逆向：

| 项目       | 值                                                                                      |
| -------- | -------------------------------------------------------------------------------------- |
| Base URL | `https://ima.qq.com`                                                                   |
| 知识库线     | `/openapi/wiki/v1`                                                                     |
| 笔记线      | `/openapi/note/v1`                                                                     |
| 协议       | HTTP POST + JSON body                                                                  |
| 认证       | 三个请求头：`ima-openapi-clientid` / `ima-openapi-apikey` / `Content-Type: application/json` |
| 返回       | `{ code, msg, data }`，`code == 0` 为成功                                                  |
| 分页       | `cursor` + `limit`，响应带 `next_cursor` / `is_end`；**各接口上限不同，见下**                         |
| 正文       | `get_media_info` 取**临时签名 URL**（自助下载），笔记走 `get_doc_content`                             |

> ⚠️ **`limit` 上限各接口不统一，不能共用一个数字。**  
> 服务端对越界值是**直接报错**而非静默截断：  
> `{"code":51,"msg":"invalid XxxReq.Limit: value must be inside range (0, N]"}`。  
> 实测边界（2026-10-07）：
>
> | 接口                               | 上限     |
> | -------------------------------- | ------ |
> | `search_knowledge_base`（列库 / 搜库） | **20** |
> | `get_knowledge_list`（浏览目录）       | 50     |
> | `search_knowledge`（库内检索）         | 未设硬上限  |
>
> v0.3.0 曾把这几个统一写成 50，导致**首屏必然打不开**（列库走的是上限 20 的  
> `search_knowledge_base`）。现已按接口分别限位，并在 `api.lua` 里加了  
> `call_with_autolimit`：一旦被上面的文案拒绝，就从消息里解析出真实上限重放一次。

因为认证只是两个静态请求头，**整份插件是纯 Lua，不需要编译任何 native 库**——  
这一点和 miuread（需要交叉编译 `miucodec.cpp` 到 Kobo ARM）完全不同。

## 安装

```
# 解压后目录结构应为：
koreader/plugins/ima.koplugin/
```

1. 把 `ima.koplugin` 整个目录拷到设备的 `koreader/plugins/` 下
2. 重启 KOReader（或重载插件）
3. 主菜单 → 更多工具 → **IMA 知识库** —— 点一下**直接进入知识库列表**

### 作为觅阅的扩展使用

觅阅（miuread）内置了插件桥接层，会自动发现并收录第三方 KOReader 插件，  
**不需要修改觅阅一行代码**。装好并启用后：

```
觅阅首页 → 插件与扩展 → 已安装扩展 → IMA 知识库   （点一下直接进列表）
```

桌面模式走首页菜单按钮的「工具」，经典模式走主菜单的「觅阅 · 微信读书助手」。

> 之所以两侧都是「一级点击即进入」，是因为 `addToMainMenu` 里**刻意只注册了一个  
> 无 `sub_item_table` 的条目**。觅阅的 `native_plugins.lua` 在只抓到单个 callback  
> 条目时会走「直接执行」分支。若改回 `sub_item_table`，两侧都会退化成两级菜单。

**再快一点：首页下拉就能点**（v0.6.7 新增）。在**觅阅首页顶部区域向下滑**，  
弹出的快捷面板里会多出一格「IMA 知识库」，点一下直接进列表。

```
觅阅首页（顶部区域下滑）→ 快捷面板 → [ Wi-Fi ][ 方向锁定 ][ IMA 知识库 ] … 
```

> 这一格不在觅阅的预设里：它的面板是**白名单式**的（条目池是 17 项硬编码，  
> 上限 8 格，且没有给第三方留注册接口）。本插件是在**内存里包装它的渲染函数**、  
> 把这一格插进去的 —— 不改觅阅任何文件、不写它任何设置。  
> 完整取证与取舍见 `ima/miuread_bridge.lua` 顶部注释。

### 觅阅升级之后要做什么

**先直接装、直接用 —— 不存在"重新关联"这一步。**

本插件与觅阅之间**没有任何需要建立的绑定关系**：不注册条目、不申请授权、不写觅阅任何文件  
或设置。全部交互都是**运行时按名字挂钩**（拿到觅阅实例和方法引用、替换一次函数引用），  
而且每一处都包在 `pcall` + 类型检查里 —— **挂钩点找不到就静默跳过，最坏结果是"这个功能  
不出现"，绝不会崩**。所以觅阅更新后，大多数情况什么都不用做。
